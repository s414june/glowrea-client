# 登入風險改善待辦

本清單只記錄目前 OAuth + PKCE 登入實作中，尚未完成且值得改善的項目。密碼政策、密碼暴力破解、MFA 與 SQL injection 不適用於目前由 Mastodon 處理帳密的登入流程，因此不列為本專案登入待辦。

## 待辦

### P1：登出時撤銷 Mastodon access token

- [ ] 登出前從有效 session 解出 access token，呼叫 Mastodon `POST /oauth/revoke`。
- [ ] 無論上游撤銷成功或失敗，都清除本地 session cookie，避免登出被上游故障阻擋。
- [ ] 撤銷失敗時只記錄不含 token 的診斷資訊，避免憑證進入 log。

**原因：**目前登出只清除瀏覽器 cookie；若 access token 曾外洩，清除 cookie 不會讓 Mastodon 端的 token 失效。

### P1：避免瀏覽器返回鍵顯示已登出的受保護內容

- [ ] 對含登入資料的 SSR 頁面與回應設定 `Cache-Control: no-store`。
- [ ] 從 BFCache 還原受保護頁面時重新確認 session，無效時清除畫面並導向登入頁。

**原因：**目前路由 middleware 會在一般導覽時確認 session，但沒有明確禁止敏感頁面快取，也沒有處理 BFCache 還原。

### P2：限制 OAuth 端點請求頻率

- [ ] 對 `POST /api/auth/start` 與 `GET /api/auth/callback` 設定速率限制與合理的請求逾時。
- [ ] 若應用部署多個 instance，使用共用的限流儲存或部署平台的 edge rate limit，不以單一程序記憶體計數。

**原因：**目前登入端點沒有應用層速率限制，可能遭大量請求消耗資源或干擾正常 OAuth 流程。
