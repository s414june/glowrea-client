# Feature: 探索與搜尋（Explore）

## Goal

提供主動探索內容的入口，讓使用者不只依賴時間軸，也能搜尋帳號、標籤、貼文，或瀏覽熱門趨勢內容。

訪客與已登入使用者均可使用搜尋與趨勢瀏覽；部分結果（如完整帳號搜尋）需登入才能使用。

---

## Scope

### In Scope

- 搜尋框：輸入關鍵字後顯示結果（帳號 / 標籤 / 貼文）
- 搜尋結果分 tab 顯示：貼文、帳號、標籤
- 趨勢標籤列表（`GET /api/v1/trends/tags`）
- 顯示 loading / empty / error state
- 訪客可瀏覽趨勢，已登入使用者可全功能搜尋
- 複用 `StatusItem`、`LoadingSkeleton` 等現有元件

### Out of Scope

- 搜尋建議 / autocomplete
- AI 推薦或個人化排序
- 搜尋進階篩選（語言、日期範圍）
- 跨 instance 搜尋
- Hashtag timeline（點擊 hashtag 進入獨立頁面，另立 feature）

---

## User Story

作為使用者，我希望能在搜尋框輸入關鍵字後找到相關的貼文、帳號或標籤；作為訪客，我希望能瀏覽目前熱門的標籤，了解社群正在討論什麼。

---

## User Flow

### 搜尋流程

1. 使用者在搜尋框輸入關鍵字
2. 按下 Enter 或搜尋按鈕
3. 顯示搜尋結果，分 tab：貼文 / 帳號 / 標籤
4. 點擊結果項目導向對應頁面
5. 清空搜尋框後回到趨勢視圖

### 趨勢流程

1. 使用者進入 `/explore`、`/explore/accounts`、`/explore/tags` 或 `/explore/links`
2. 顯示對應分類的熱門內容
3. 點擊標籤導向對應標籤頁面（`/tags/:tag`）

---

## Route

### Path

- `/explore`：熱門貼文
- `/explore/accounts`：熱門帳號
- `/explore/tags`：熱門標籤
- `/explore/links`：熱門連結

### Route Guard

- 無保護，訪客可直接存取

### Route Responsibility

- `/explore` 父頁負責共用搜尋框、分類導覽與搜尋狀態
- 子路由分別顯示貼文、帳號、標籤或連結
- 使用 Nuxt 預設檔案路由，不另設 router 設定

---

## UI Requirements

### 頁面結構

```
┌──────────────────────────────────────┐
│ 搜尋框                                │
├──────────────────────────────────────┤
│ [貼文] [帳號] [標籤]                  │  ← 有搜尋關鍵字時顯示
├──────────────────────────────────────┤
│ [貼文] [帳號] [標籤] [連結]           │  ← 無搜尋關鍵字時顯示熱門內容
└──────────────────────────────────────┘
```

**路由行為：**
- 分類導覽使用 NuxtLink，路徑分別為 `/explore`、`/explore/accounts`、`/explore/tags`、`/explore/links`
- 有搜尋關鍵字時隱藏連結分類（Mastodon search API 不支援連結類型）；若目前在 `/explore/links`，輸入關鍵字後導回 `/explore`

### 搜尋框

- placeholder：「搜尋」
- 輸入後即時更新 tab 內容（debounce 300ms）或按 Enter 送出

### 搜尋結果 Tabs

| 路由 | 搜尋結果 |
|-----|---------|
| `/explore` | 匹配貼文，複用 `StatusItem` |
| `/explore/accounts` | 帳號卡片（頭像 + 名稱 + handle + 簡短描述） |
| `/explore/tags` | 標籤名稱 + 使用次數 |

### 熱門內容 Tabs（未搜尋時）

| 路由 | API | 顯示內容 |
|-----|-----|---------|
| `/explore` | `GET /api/v1/trends/statuses` | 熱門貼文，複用 `StatusItem` |
| `/explore/accounts` | `GET /api/v1/directory?order=active` | 活躍帳號卡片 |
| `/explore/tags` | `GET /api/v1/trends/tags` | 標籤名稱 + 近期使用次數 |
| `/explore/links` | `GET /api/v1/trends/links` | 文章卡片（標題 + 來源網域 + 縮圖 + 作者） |

### 趨勢連結卡片

### 趨勢連結卡片

- 縮圖（若有）置於左側或頂部
- 標題（粗體）+ 來源網域 + 作者名稱（若有）
- 點擊以 `target="_blank"` 開啟外部連結

### 趨勢標籤（標籤 tab）

### 趨勢標籤（標籤 tab）

- 顯示 tag 名稱 + 近期使用次數
- 可點擊（導向 `/tags/:tag`）

### Loading State

- 使用現有 `LoadingSkeleton` 元件

### Empty State

- 搜尋無結果：「找不到相關內容」
- 趨勢各 tab 為空：「目前沒有熱門貼文 / 帳號 / 標籤 / 連結」

### Error State

- 顯示錯誤訊息 + Retry 按鈕

## 資料流

### 搜尋 API Endpoint

`GET /api/search`

query params：
- `q: string`（必填）
- `type?: 'accounts' | 'statuses' | 'hashtags'`（省略時全類型）
- `limit?: number`（預設 20）

### 對應 Mastodon API

```
GET /api/v2/search?q={q}&type={type}&limit=20
```

已登入時帶 Authorization header；訪客不帶（搜尋功能受限）。

### 趨勢連結 API Endpoint

`GET /api/trends/links`

### 對應 Mastodon API

```
GET /api/v1/trends/links?limit=20
```

不需要 Authorization header（公開端點）。

### 趨勢 API Endpoint

`GET /api/trends/tags`

### 對應 Mastodon API

```
GET /api/v1/trends/tags?limit=20
```

不需要 Authorization header（公開端點）。

### 回傳格式

```ts
type SearchResponse = {
  accounts: AccountSummary[]
  statuses: TimelineStatus[]
  hashtags: HashtagItem[]
}

type HashtagItem = {
  name: string
  url: string
  history: { day: string; uses: string; accounts: string }[]
}
```

## 錯誤處理

| 情境 | 行為 |
|------|------|
| 搜尋 API 回傳非 2xx | 前端顯示 error state |
| 趨勢 API 失敗 | 靜默略過，顯示空列表 |
| 關鍵字為空字串 | 不送出搜尋，顯示趨勢視圖 |
| 網路錯誤 | 前端顯示 error state + retry |
