# Feature: Login / Logout（固定伺服器）

## Goal

提供最小可用的登入與登出流程，讓使用者可以進入受保護頁面（`/timelines`）並在需要時安全登出。

此階段採 OAuth 2.0 Authorization Code + PKCE，讓固定 Mastodon 實例上的任何帳號都能以自己的授權頁登入（連線實例由部署端固定，使用者無法自行切換聯邦伺服器），優先驗證：

- 登入狀態切換是否正確
- route guard 與頁面導向是否清楚
- token 使用與清除是否一致
- 錯誤狀態是否可被使用者理解與恢復

---

## Scope

### In Scope

- 固定伺服器登入（Mastodon 實例由部署端設定，不支援切換聯邦伺服器）
- OAuth 2.0 Authorization Code + PKCE 登入流程（由 Mastodon 實例控管授權頁，不在 Glowrea 輸入帳密）
- 登入成功後可進入 `/timelines`
- 未登入使用者不可進入 `/timelines`
- 使用者可從已登入狀態登出
- 登出後返回未登入入口（`/login`）
- 基本 loading / error UI
- 基本 session 狀態管理（client side）

### Out of Scope

- 切換聯邦伺服器（使用者自行選擇 Mastodon 實例）
- 多帳號管理與快速切換
- 記住我、裝置管理、2FA
- 密碼重設、註冊流程
- SSO / 第三方登入
- 權限分級（admin/moderator 等）

---

## User Story

作為使用者，我希望能登入後使用首頁時間軸，並在離開裝置或切換使用情境時能安全登出，避免他人繼續使用我的登入狀態。

---

## User Flow

1. 使用者進入 `/login`
2. 點擊登入按鈕，前端呼叫 `/api/auth/start` 取得 Mastodon 授權 URL
3. 登入中顯示 loading，避免重複提交
4. 瀏覽器跳轉至 Mastodon 授權頁，使用者同意授權
5. Mastodon 導回 `/api/auth/callback`，server 驗證、交換 token、建立 session，再導向 `/timelines`
6. 若登入失敗，顯示可理解的錯誤訊息與重試入口
6. 已登入使用者在 `/timelines` 可觸發登出
7. 系統清除 session 狀態後導向 `/login`
8. 登出後若再訪問 `/timelines`，應被導向 `/login`

---

## Route

### Paths

- `/login`：登入入口頁
- `/timelines`：登入後主頁（受保護）

### Route Responsibility

- `login route`
  - 提供登入入口與狀態呈現（idle/loading/error）
  - 不處理 timeline 資料
- `home route`
  - 僅在登入狀態下可進入
  - 不負責登入憑證交換

### Route Guard Rules

- 未登入存取 `/timelines`（或任何受保護路由）→ 導向 `/login`
- 已登入存取 `/login` → 導向 `/timelines`
- 登出完成後，任何受保護路由都應視為未登入
- 根路由 `/` → 依登入狀態重導向（已登入 `/timelines`、未登入 `/login`），以 `replace: true` 取代歷史記錄
- 不存在的路由 → 由 Nuxt error page（`app/error.vue`）顯示 404，**不導向 `/login`**
  - 403（未授權）與 404（不存在）行為完全分開，避免混淆

## UI Requirements

### Login Page

- 明確頁面標題（例如：登入 Glowrea）
- 主要登入操作按鈕
- 登入中狀態（disable 按鈕 + loading 文案）
- 錯誤訊息區塊（可重試）

### Logout Entry

- 在登入後可見位置提供登出入口（例如 header/menu）
- 登出中應暫時 disable 重複操作

### Feedback States

- Login loading: 顯示「登入中...」或等效狀態
- Login error: 顯示可理解訊息（例如：授權失敗、網路異常）
- Logout success: 導向 `/login` 視為成功回饋

## State Model

### AuthState

```ts
type AuthState = {
  isAuthenticated: boolean
  isLoading: boolean
  errorMessage: string | null
  accountId: string
}
```

### Notes

- `accountId` 為 OAuth 登入帳號在固定 Mastodon 實例上的 ID。
- 不維護 account list（同一實例多帳號登入與切換為 Future Extension）。

---

## Data & Session Strategy

- OAuth 完成後，server 將 access token 以 AES-256-GCM 加密，一同封裝入 session cookie（httpOnly）。
- 不使用外部 KV 儲存（無需 Redis）；token 随使用者 session 生命週期自然失效。
- client 端只管理「是否已登入」與 UI 狀態，不直接持久化敏感 token。
- 登出時清除 session cookie，client 端 auth state 及相關暫存資料一並重置。

## Mastodon API 介接方式

### Integration Goal

- client 不直接呼叫 Mastodon OAuth/token 端點。
- 所有敏感資訊（client secret、access token）只存在 server 端。
- 前端只與本專案的 server API 溝通。

### Phase A（舊版／本機開發備用—固定 token）

由 server runtime config 提供固定 access token，前端「登入」僅建立本地 session。目前已被 Phase B 取代，係開發端帳腐機用。

### Phase B（目前實作—OAuth 2.0 + PKCE，固定伺服器）

**Mastodon 實例由部署端固定，使用者無法自行選擇實例。** 任何在該實例上有帳號的使用者都可以登入。

**必需環境變數：**

| 變數 | 用途 |
|---|---|
| `NUXT_MASTODON_API_BASE` | Mastodon 實例地址（固定） |
| `NUXT_MASTODON_CLIENT_ID` | OAuth App client_id |
| `NUXT_MASTODON_CLIENT_SECRET` | OAuth App client_secret |
| `NUXT_AUTH_SESSION_SECRET` | Session cookie 簽名與 token 加密金鑰 |

**OAuth App 註冊（一次性作業）：**

```sh
curl -X POST https://{instance}/api/v1/apps \
  -F 'client_name=Glowrea' \
  -F 'redirect_uris={REDIRECT_URI}' \
  -F 'scopes=read write follow'
```
將回傳的 `client_id` / `client_secret` 寫入環境變數。

**登入流程：**

1. 前端呼叫 `POST /api/auth/start`。
2. server 產生 `state`、`code_verifier`、`code_challenge`，將 `state + codeVerifier` 封裝為短效 httpOnly cookie，回傳 `{ authorizationUrl }`。
3. 前端跳轉至 Mastodon 授權頁（實例固定）。
4. 使用者在 Mastodon 授權頁登入並同意後，Mastodon 導回 `GET /api/auth/callback?code=...&state=...`。
5. server 驗證 state，將 code + code_verifier 向實例交換 access token。
6. server 呼叫 `GET /api/v1/accounts/verify_credentials` 取得帳號資訊。
7. server 將 access token 以 AES-256-GCM 加密，封裝入 session cookie（httpOnly），導向 `/timelines`。

Mastodon 相關端點：

- `GET /oauth/authorize`（導向使用者授權）
- `POST /oauth/token`（交換 token）
- `POST /oauth/revoke`（可選，登出時撤銷 token）
- `GET /api/v1/accounts/verify_credentials`（取得登入帳號資訊）

### Logout 與 Token 策略

- 必做：清除 session cookie。
- 選做：呼叫 Mastodon `POST /oauth/revoke` 撤銷 access token（產品希望強制失效時啟用）。
- token 存在 session cookie 內，清除 cookie 即可斷開所有 API 存取權限。

### 固定伺服器限制（本期）

- server 僅維護一個固定的 Mastodon 實例（`NUXT_MASTODON_API_BASE`），不接受來自前端的實例參數。
- 同一實例下任何帳號均可透過 OAuth 登入；不支援切換到其他實例。

---

## Error Handling

- 登入 API 失敗：顯示錯誤 + 可重試
- 網路超時：顯示通用錯誤，建議重試
- 未授權（401/403）：視為未登入，導向 `/login`
- 登出 API 失敗：保留在當前頁並提示重試（避免誤判已登出）

---

## Security Requirements

- 不在 client local storage 明文保存 access token（若非必要）。
- 所有受保護資料請求需經 server 端代理，避免 token 暴露在瀏覽器。
- 登出後應防止以瀏覽器返回鍵直接看到受保護內容（至少需重新驗證 auth state）。

---

## Acceptance Criteria

1. 未登入時進入 `/timelines`，會被導向 `/login`。
2. 在 `/login` 點擊登入後，瀏覽器跳轉至 Mastodon 授權頁。
3. 使用者在 Mastodon 授權後，會被導向 `/timelines`。
4. OAuth 過程失敗時有錯誤訊息，且可再次嘗試登入。
4. 已登入狀態進入 `/login`，會被導向 `/timelines`。
5. 已登入狀態進入 `/login`，會被導向 `/timelines`。
6. 在 `/timelines` 觸發登出後，會導向 `/login`。
7. 登出後重新進入 `/timelines` 仍會被導向 `/login`。
8. 全流程僅支援固定伺服器，UI 上無切換聯邦實例的入口或資料結構依賴。
